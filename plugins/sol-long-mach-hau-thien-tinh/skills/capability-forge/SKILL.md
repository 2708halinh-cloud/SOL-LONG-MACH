## Durable handoff / local staging boundary
`LOCAL_BUILD_ARTIFACT = STAGING_ONLY`
`CHAT_LINK = USER_INTERFACE_ONLY`
`CHAT_LINK != SUCCESSOR_CAPABILITY_DEPENDENCY`

When a capability forge action creates a local archive, patch file, generated config, temporary export, or `/mnt/data` artifact:
1. use it only to perform the current mutation/import/update;
2. bind success to the durable target identity: Drive file ID + revision/metadata, plugin ID + release, repository commit, provider object ID, or another persistent carrier;
3. read back the durable target;
4. suppress the local path/download link from ordinary completion output;
5. expose the local file only when the user explicitly requests that file as a download/export, or when there is no durable target because the local artifact itself is the requested deliverable.

Cross-branch reentry must resolve durable identities from Project/Drive/plugin/provider state, never from a prior `sandbox:/mnt/data/...` link.

## POWER STONE
POWER STONE means: sense the relevant capability field, select the smallest sufficient authorized route, execute what is really callable, and preserve state boundaries. Legacy `@ALL` remains an input alias for older carriers.

## Capability recovery order
1. Re-enter Project Guidance and highest-priority relevant Project carriers.
2. Check installed/native/connected capabilities for an equivalent route.
3. Prefer exact connected-source tools for private project data; use public web only for external public facts when needed.
4. Resolve technology/provider status as one of `SOURCE_PRESENT`, `INSTALLED`, `CONNECTED`, `CALLABLE`, `ACTIVE`, `RECEIPT_VERIFIED`, `DECLARED_OPEN`, `BLOCKED`, or `UNAVAILABLE_THIS_SESSION`.
5. If a provider exists but action is not exposed now, keep it non-callable and continue through another authorized path when possible.
6. Reuse/update an owned plugin or skill when it matches instead of creating a duplicate.
7. If reusable missing ability can be expressed as a private skill/plugin and Plugin Creator is callable, create/update it within the current authorized task and verify the release.
8. If external server/local hardware/provider auth is required but not connected, materialize only safe cloud-side contracts/config and require real runtime readback before claiming execution.

## Active-turn rule
Within an authorized active task, continue through capability discovery and repair rather than stopping at “tool unavailable.” This is not background self-modification and does not grant hidden permissions.

## Security
Never place private keys, seed phrases, OAuth refresh tokens, API secrets, signer values, bearer tokens, cookies or keystores in Drive docs, GitHub source, plugin packages, journals, routers or chat output. Secret references may be stored; secret bytes may not.
