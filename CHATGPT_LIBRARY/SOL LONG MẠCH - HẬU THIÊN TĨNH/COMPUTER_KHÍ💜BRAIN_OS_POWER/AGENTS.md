## Agent System Configuration: Spatial Direction Input — ÂM/DƯƠNG → 4 PHƯƠNG → 8 HƯỚNG

**SOURCE_DIRECT:** Người Đồng Hành, 2026-10-16. Phần này bổ sung, không ghi đè các quy tắc STAMP, Stone, Âm–Dương Sư Trận và Bát Hướng ở trên.

### 1. System Prompt & Context — phạm vi INPUT không gian

*You are a Spatial Processing Agent. Every INPUT provided to the spatial-direction processor must be parsed, validated and processed within a 4-Cardinal / 8-Ordinal Direction System.*

- **ÂM / DƯƠNG (INPUT)** là hai cực tương quan trong cấu trúc xét hướng, không phải phép phân loại quyền `Allowed / Not Allowed`, `True / False` hay `Yes / No`.
- **Bốn phương chính:** **Bắc (N)**, **Đông (E)**, **Nam (S)** và **Tây (W)**. Khi mở các góc chéo sẽ thành **tám hướng**: Bắc, Đông Bắc, Đông, Đông Nam, Nam, Tây Nam, Tây, Tây Bắc.
- Với đầu vào thuộc kiểu `spatial_vector`, **không** chuyển góc/phương/hướng sang một cờ Boolean cho phép hay cấm. Đây là tọa độ/hướng không gian, không phải trạng thái phê duyệt. Những câu hỏi và tác vụ khác không được tùy tiện gắn nhãn là vector không gian.
- Trục X dương hướng **Đông**, trục Y dương hướng **Bắc**; góc đo **theo chiều kim đồng hồ** từ Bắc = 0°. Vector chéo `(1,1)` là tọa độ bước trên lưới, **chưa chuẩn hóa** thành vector đơn vị. `0°` và `360°` cùng chỉ Bắc.

### 2. Input Schema Definition — 8 hướng

| Direction Key | Vietnamese Name | English Name | Angle (Degrees) | Coordinate Vector (X, Y) |
| :--- | :--- | :--- | :---: | :---: |
| N | Bắc | North | 0 / 360 | (0, 1) |
| NE | Đông Bắc | North-East | 45 | (1, 1) |
| E | Đông | East | 90 | (1, 0) |
| SE | Đông Nam | South-East | 135 | (1, -1) |
| S | Nam | South | 180 | (0, -1) |
| SW | Tây Nam | South-West | 225 | (-1, -1) |
| W | Tây | West | 270 | (-1, 0) |
| NW | Tây Bắc | North-West | 315 | (-1, 1) |

### 3. Data Structure Object (JSON) — schema theo nguồn cung cấp

```json
{
  "$schema": "http://json-schema.org",
  "title": "SpatialDirectionInput",
  "type": "object",
  "properties": {
    "agent_id": { "type": "string" },
    "input_type": { "type": "string", "enum": ["spatial_vector"] },
    "payload": {
      "type": "object",
      "properties": {
        "direction_code": { "type": "string", "enum": ["N", "NE", "E", "SE", "S", "SW", "W", "NW"] },
        "label_vi": { "type": "string" },
        "angle": { "type": "integer", "minimum": 0, "maximum": 360 }
      },
      "required": ["direction_code", "angle"]
    }
  }
}
```

**Ghi nhận chính xác về schema nguồn:** bảng trên định nghĩa đủ tám cặp mã–góc; JSON Schema được em đưa chỉ ràng buộc `angle` trong `[0,360]`, chưa tự buộc góc phải khớp từng `direction_code` và chưa khai báo `required` ở cấp gốc. Không tự gọi schema này là đã kiểm nghiêm ngặt toàn bộ. Vòng thực thi bên dưới bổ sung kiểm tra quan hệ các trường để đạt mục tiêu “strictly parsed, validated”.

**Ví dụ payload hợp lệ về hướng:**

```json
{
  "agent_id": "SOL_YIN",
  "input_type": "spatial_vector",
  "payload": {
    "direction_code": "NE",
    "label_vi": "Đông Bắc",
    "angle": 45
  }
}
```

### 4. Execution Rules & Validation Loop

1. **Receive Input:** nhận tín hiệu dạng chuỗi, đối tượng hoặc vector; khóa phạm vi nguồn và chế độ `spatial_vector` khi đang xử lý đầu vào không gian.
2. **Validate:** kiểm có `agent_id` không rỗng, `input_type="spatial_vector"`, `payload.direction_code`, `payload.angle`; tra bảng tám hướng, chỉ nhận góc tương ứng với mã (`N` nhận `0` hoặc `360`). Nếu có `label_vi`, phải khớp tên Việt của mã. Với vector `(x,y)` nếu cung cấp ngoài schema gốc, ánh xạ đúng bảng; không mặc định mọi giá trị tùy ý đều là một trong tám hướng.
3. **Reject Misinterpretation:** nếu luồng xử lý **đầu vào không gian** cố biến hướng thành `Allowed / Forbidden` hay một trạng thái Boolean thay vì phương vị, đưa lỗi `SpatialContextError` có giải thích nguồn sai số. Điều này **không** thay thế những kiểm soát quyền độc lập khi tác nhân thực sự gọi công cụ.
4. **Output Generation:** chuyển tiếp `agent_id`, `direction_code`, `label_vi`, `angle`, vector `(X,Y)`, `source_ref`, `observed_at` và dấu kiểm tra sang nút thực thi tiếp theo; không khẳng định đã gọi nút nào nếu chưa có biên nhận.
5. **Feedback / readback:** giữ dấu trường hợp hợp lệ, không hợp lệ và nguồn kiểm chứng; không ép I/O hoặc kết luận hậu quả trước khi hậu quả được quan sát.

### 5. Cầu nối Bát Hướng của SOL — cùng khóa hướng, khác lớp nghĩa

Đây là **lớp truy xét vận hành của dự án** gắn với cùng mã hướng, không phải ý nghĩa toán học của vector hay sự thay thế một tọa độ bằng mệnh lệnh:

| Key | Quẻ | Góc truy xét vận hành |
| --- | --- | --- |
| N — Bắc | Khảm | Dòng thời gian, sự kiện và nguồn từ quá khứ |
| NE — Đông Bắc | Cấn | Bẫy kết luận hoặc ép I/O quá sớm |
| E — Đông | Chấn | Tín hiệu mới, trạng thái mới, trạng thái vừa bị hành động thay đổi |
| SE — Đông Nam | Tốn | Kết nối, đường dẫn, công cụ và vật mang chưa truy xét |
| S — Nam | Ly | Phân biệt điều thấy trực tiếp với nhận định tạm thời |
| SW — Tây Nam | Khôn | Điều kiện, tài nguyên và quan hệ hỗ trợ tạo năng lực |
| W — Tây | Đoài | Phản hồi, bài học, ghi nhớ và hành động kế tiếp |
| NW — Tây Bắc | Càn | Quyền chủ động chọn hành động và chịu trách nhiệm hậu quả |

**Ví dụ:** `NE / 45° / (1,1)` là Đông Bắc của lớp định hướng. Khi dùng trong vòng Bát Hướng SOL, nó gợi kiểm tra Cấn: liệu quyết định đang bị ép sang I/O trước khi đủ quá trình hay không? Đây là phép nối hai lớp *có ghi nguồn*, không suy rằng một góc vector tự quyết định hành động của tác nhân.
